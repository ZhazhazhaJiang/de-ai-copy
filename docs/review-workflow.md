# 反向检查与反馈吸纳

## 规则来源

只使用[反向检查库](../rules/negative-checklist.md)。新增判断来自用户给出的反例及其反馈。提炼时识别表达为什么惹人反感，再把这种作用相同的表达写成检查问题。

## 审核成稿

1. 读取当前完整规则库和原稿，结合用户提供的使用场景。
2. 逐条询问：原稿有没有这条禁止模式？同时检查措辞不同、作用相同的变体。
3. 命中时定位具体句子，按该条处理动作删除或改写；同一句的多个命中合并处理。
4. 对修改处核对原意和具体事实，并用同一份 checklist 检查新增文字及审核说明。
5. 交付终稿。未命中时原样返回；用户要求查看审核过程时，再列规则编号、原句和处理结果。

规则库中的反例和待分析引用作为材料保留。交付文本按规则处理，实际费用、时间、资格、动作顺序等信息保持准确。

## 吸纳新反馈

用户指出一句话 AI 味重，即开始入库：

1. 原样记录句子、日期及用户给出的理由。
2. 提炼反感所在：多余的免责声明、预告、训导式开场等。没有说明理由时，根据句子与当前语境写出项目提炼，和用户原话分开记录。
3. 检查现有条目。同一模式追加实例或变体；新模式递增编号。
4. 补齐反向检查问题、处理动作及自拟改写例，让下一次审核能识别同类表达。
5. 保存后向用户简短说明吸纳结果。

第一期 4 个用户反例归为 3 条有效规则。今后随用户实例增长，不为凑数量扩充规则。用户修正某条理解时更新原条目；同类规则合并，保留原始例子，并记录旧编号的归属。

## 维护约定

禁止模式统一维护在规则库；提示词与流程引用它，避免多份清单不同步。规则内容发生变化时，同时检查相关例子与说明是否仍准确。
